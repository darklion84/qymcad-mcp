# ADR 0045: Colour in exports and visible_only

- Status: accepted (2026-11-03).
- Related: ADR 0022, ADR 0028, ADR 0042, ADR 0044; F-020, F-069, F-073, F-133.

## Context

E3 persists native body appearance. Its explicitly temporary output contract keeps exports colourless and includes hidden current result bodies. The native app already carries manual and palette colour, imported face overrides and mesh triangle colours through its public tree writers. The app also filters hidden bodies before constructing that tree. The server needs the colour path while preserving its flat body selection, geometry and default output membership.

## Decisions

1. Write 3MF and GLB with `qymcad_io::export_3mf_tree` and `export_glb_tree`; write STEP with `qymcad_kernel::write_step_tree` under the existing caller-held kernel gate. Build one independent node per selected current body, without introducing assembly operations or substituting a component's active body. Use native `mesh_color(mesh_index(id))`, including palette fallback, and retain the lineage's imported `face_colors`. The stale palette comment in native `io_jobs.rs:733` does not describe `Project::export_node`'s actual colour selection.
2. Preserve world placement exactly once, with identity placement on every flat root node. Meshes retain the existing world-coordinate transform. Native 3MF and STEP tree writers apply placement only to child occurrences, so a flat STEP root requires a world-transformed Shape. For nonidentity world placements, obtain independent named Shape copies through `session::copy_shapes` before acquiring the outer gate, then transform those copies with public `Kernel::transform_body` in an isolated `OcctKernel` under a caller gate; retain original live shapes untouched. Identity placements reuse the original Shape. Do not add an artificial assembly root. Keep existing tessellation deflections, weld policy, triangle winding, private staging directory and atomic rename.
3. Preserve imported per-triangle mesh colours and convert imported B-rep face colours to triangle colours using the fresh tessellation's persistent face ids and triangle indices, as the app does. Keep fallback body colour for unoverridden faces. Carry the colour array through weld using surviving input-triangle indices; removing a degenerate triangle removes its colour slot. STL and OBJ continue through their existing colourless flat writers.
4. Add top-level `colors` to export results: true for 3MF/GLB/STEP, false for STL/OBJ. Each exported body reports `color_rgb` from native `mesh_color` and `color_source: "manual"|"palette"`, using lineage-map membership as in ADR 0044. These describe body appearance even in a colourless format or when imported overrides colour individual faces or triangles.
5. Add optional `visible_only: bool = false` to both `export` and `render`. False preserves the current result-body selection, including hidden bodies, for omitted and explicit `bodies`. With true and omitted `bodies`, select visible current bodies and report excluded ids in `skipped_hidden`. With true and explicit `bodies`, refuse any hidden selected body and name it; never silently write a partial explicit selection. Refuse an empty visible selection. Preserve existing current-body, empty-list, regeneration-error and reference-validation rules. No other default changes.
6. Resolve visibility and refuse before creating a staging directory or writing a target. Export/render remain inspection/output operations outside modelling batch and undo. Selection failure preserves full document information, topology and existing output files. Export reports `skipped_hidden`; render returns the same information with its image caption.
7. Preserve the previous flat writers' output naming: 3MF/GLB objects are `body_1`, `body_2`, … in selected file order; STEP node names are empty, matching the old unlabelled flat STEP path. Do not copy native body/component labels into exchange-file object names as a side effect of adding colour. Existing import filename fallbacks, source indexes, selection and label resolution retain ADR 0028 semantics. Report fields `name` and `body_name` retain ADR 0042 semantics independently of these exchange-file labels.

## Compatibility and verification

This ADR implements the E4 exception explicitly reserved by ADR 0044: colour now reaches 3MF/GLB/STEP and visibility filtering is opt-in. The default body membership, flat file naming and the colourless renderer remain compatible; STL/OBJ bytes do not depend on body colour. The existing `import_tool::importing_multiple_solids_preserves_names_indices_and_selection` contract remains unchanged: adding colour must not displace imported filename fallback names with native body labels. Persisted sketch visibility remains unsupported under the pin, so T7 remains partial.

Acceptance lives in `crates/engine/tests/golden_export_color.rs` and `crates/mcp/tests/e4_export_color.rs`. Independent XML, GLB JSON/binary and STEP text/read-back checks use a 10 × 20 × 4 = 800 mm³ prism, RGB `[17,34,51]`, the hand sRGB-to-linear equation and hand-computed moved bounds. Comparisons to the original flat native writers protect geometry and placement; coloured-import checks protect override assignment and triangle counts. Refusals compare before/after document information and topology and check target/staging absence. `tasks/E4-report.md` and `tasks/E4-logs/` record failing-first runs, final verification, changed E3 assertions and restored production mutations. Native-source and retained research evidence are separately identified in F-133.

# ADR 0033: Native body move and rotation

- Status: accepted (2026-10-30).
- Related: ADR 0028, F-024, F-074, F-104, F-116, F-117.

## Context

Pinned QymCAD stores a body Move as a rigid 3×4 transform. Only its total affine translation slots, `dx`, `dy` and `dz`, have native formula and named-dimension support. The app reuses a Move node for a subsequent body drag. Native accumulation rounds formula deltas and cannot correctly rotate a parameter-driven translation into another axis.

## Decisions

1. Add `move` with optional `body` (the normal current-body default), either one or more top-level `dx`, `dy`, `dz` values of type `Num`, or `rotation:{angle,axis,pivot?}`. Omitted translation axes are zero; translation and rotation are mutually exclusive. Rotation angle is a finite literal in degrees, axis is `x`, `y` or `z`, and pivot is a literal three-vector. Axes and pivot use the source part's local frame. The default pivot is the current display-mesh bounding-box centre, sampled once as in the app; later source edits do not resample it.
2. Use the app's public core path: `Project::add_move` for a new Move and `Project::accumulate_move` for an existing Move. The latter retains both feature and output-body id. Report `reused` so callers can distinguish creation from reuse. Compose new operations after previous operations, matching the app. A requested name follows the normal object-name rules, including reuse.
3. Persist translation through native `write_feat_formula`. After native accumulation, reconstruct every affected dx/dy/dz expression from its pre-edit expression or matrix slot plus the requested displacement, using full-precision decimal text. Never retain the rounded expression generated by `accumulate_move`. Apply the existing formula validation and naming paths to the resulting expressions.
4. Allow a first rotation and accumulated rotations of a plain numeric Move. Refuse rotation onto a Move with a nonliteral shift expression, with the reason: `rotation accumulation on a formula-driven Move is unsupported: native accumulate_move adds numeric deltas to stored translation formulas instead of rotating their variable coefficients` (F-116). Do not bake the current parameter value or create a fresh node to evade that refusal; either choice changes the promised dependency or reuse contract. Plain numeric shift formulas remain eligible for rotation; arithmetic expressions are conservatively treated as formulas.
5. `dimension_set` exposes exactly native `dx`, `dy`, `dz` on Move. They are the transform's total affine translation in mm, including a rotation pivot's `pivot − R·pivot` contribution; they are not independent rotation angles or necessarily the last gizmo displacement. Angle and pivot remain literal matrix data.
6. Preserve native source ownership, including imported parts (ADR 0028), and restore the active modelling context. Native persistent face and edge names pass through the transform. A Move creates no new topology roles, so `OfFeature(move)` must not invent faces or edges.
7. Establish a clean baseline, then apply recipe changes and propagate changed native named dimensions in a recipe transaction. Solve sketches and dirty feature consumers of those names, including independent bodies that do not consume the moved body geometrically. Compute the rebuild plan after propagation, then snapshot every planned live B-rep before regeneration. Any propagation, native rebuild or acceptance error restores the pre-edit recipe, original B-reps and diagnostics. Evaluate the returned transform from the settled post-rebuild scope. Retain ordinary history, batch and undo boundaries, F-024 stored-selection preflight and F-074 fillet validation. Never hold `kernel_gate` while invoking self-gating regeneration or restore functions.

## Consequences

Translation formulas and named native shift drivers remain editable after save/load through the app's parameter scheduler. Rotations retain the app's literal-angle scope and sampled pivot. Repeated translations preserve full precision and node identity; the unsupported formula-driven rotation accumulation is an explicit atomic refusal.

# ADR 0047: History rollback

- Status: accepted (2026-11-03); stage acceptance is recorded separately in `tasks/E7-report.md`.
- Related: ADR 0008, ADR 0012, ADR 0020, ADR 0033, ADR 0038, ADR 0041, ADR 0042, ADR 0046; F-008, F-024, F-069, F-073, F-074, F-128, F-135.

## Context

QymCAD's history marker selects an active prefix of the complete timeline, including sketch and datum nodes. Moving the marker changes the current result without deleting the inactive recipe. Native creation at the marker inserts a node, advances the marker and can rewire the first later consumer. ADR 0046 already gives inspection, topology, measurement, export, render and open a shared active-result definition; changing the marker must preserve that definition and the existing rebuild failure guarantees.

## Decisions

1. Expose `history_rollback` with exactly one of `{"after": ObjRef}`, `{"position":"start"}` or `{"position":"end"}`. Deny unknown fields and refuse both/neither selector, unsupported position strings and unknown or ambiguous references before mutation. No raw timeline index is exposed. `after` resolves a timeline node using the normal id/name rules; sketches and datums are valid because they have native timeline positions. A parameter or body without a matching timeline node is refused.
2. `after` sets the marker immediately after that node with `Project::set_rollback(Some(ti + 1))`; `start` uses `Some(0)` and `end` uses `None`. An `after` reference to the last timeline node canonicalizes to `None` and reports `position:"end"`. On an empty timeline the native normalized state is also `end`.
3. Return `{"position":"start|end|after","after":{"id":N,"name":...}|null,"next_feature":{"id":N,"name":...}|null,"active_nodes":N,"total_nodes":M,"changed":bool,"rebuild":{"bodies":[...],"warnings":[...],"errors":[...]}}`. For position `after`, `after` identifies the last active timeline node; it is null at start and end. `next_feature` identifies the first inactive timeline node and is null at end. Both names are normal display names, including when a node is a sketch or datum. `doc_info.rollback` exposes the same position, after, next_feature and node-count fields, without changed/rebuild.
4. For a real position change call the native setter, then the existing checked rebuild through `with_rebuild_copies`. Keep the extended rebuild dependency plan, F-024 persisted-pick/legacy empty-pool checks, F-074 fillet acceptance and all native errors. A failed tail rebuild while moving the marker down refuses the entire change even if native regeneration supplied a pass-through shape (F-008).
5. On any failure restore the exact pre-edit Project, original live B-rep handles, shape absence and diagnostics without a repair rebuild (ADR 0038/0041). Restore ordinary tool/batch state through the established history boundary, preserving ADR 0020/0042's allocator policy. Do not hold the non-reentrant kernel gate across self-gating rebuild or restore calls (F-069/F-073).
6. Requesting the same canonical position returns `changed:false`, performs no rebuild and adds no undo entry. A real change adds one undo step, or reuses the enclosing batch's boundary. Undo restores the previous marker and geometry without regeneration. A later failed batch step restores the whole pre-batch state.
7. New features continue through native `add_*` creation, so `push_timeline` inserts at the marker and advances it, remapping the first later same-parent consumer of the old source when applicable. Do not manually append a newly created node or clear the marker. Existing creating-tool result shapes remain unchanged; inspect the new marker through `doc_info`. Existing Move-node accumulation remains governed by ADR 0033; a reuse operation is not native node creation.
8. Save preserves the native marker field. Result bodies and export/render/measure/topology use only the active prefix as established by ADR 0046. At start there can be no current body without a rebuild error. Existing empty-save protection and export's no-bodies refusal remain in force. Suppressing an inactive tail node remains legal and leaves the active result body set unchanged.

## Consequences and evidence

T6 covers B-rep feature suppression and native history rollback. The owner resolved the insertion acceptance fixture by choosing a through cut C after Move M1, preserving ADR 0033 §2 Move reuse. Cut C consumes M1; native insertion remaps the later Move M2 to C. A separate acceptance test requests a move on M1 under the marker and asserts reuse, accumulated translation and unchanged node count. Body-feature suppression retains its existing mesh-born Move refusal (F-128). This does not expose reorder or broaden the suppression feature classes accepted by ADR 0046.

F-135 records native source and retained executed probes under `tasks/research-medE/history/`. Acceptance tests belong in `crates/engine/tests/golden_rollback.rs` and `crates/mcp/tests/e7_rollback.rs`; their actual failing-first, passing and mutation outcomes belong in `tasks/E7-report.md` and `tasks/E7-logs/`, not in the research evidence. The prism reference is independently 10 × 20 × h: volume 4000 mm³ at h=20 and 6000 mm³ at h=30. Initial bounds are [−5,−10,0,5,10,h]; +5X only gives [0,−10,0,10,10,h], and +7Y then gives [0,−3,0,10,17,h]. A centered interior 2 × 2 through cut preserves those outer bounds and removes 2 × 2 × h: volume 3920 mm³ at h=20 and 5880 mm³ at h=30. The test creates its sketch on a top datum z=h through the normal native adders; those support nodes also insert at and advance the marker. Timeline [profile, stock, M1, top, cut profile, C, M2] has marker Some(6) after C.

The shared `common::gui_edit_param*` test helper emulates the app's parameter schedule but selects its final body without a rollback bound. It stays unchanged. The rollback test file uses a local helper calling `common::restore_shapes` and the same native load/parameter/rebuild calls, then selects through `Project::active_body` or the native rollback prefix. This tests native saved-file scheduling rather than repairing a file through the engine; it is not manual GUI verification.

# ADR 0034: Native sketch holes with a bounded dependency bridge

- Status: accepted (2026-10-30).
- Related: ADR 0007, ADR 0008, ADR 0020, ADR 0024, ADR 0030; F-024, F-037, F-069, F-074, F-103/F-104, F-118/F-119.

## Context

The app's `Project::add_hole_from_sketch` drills every isolated point in a sketch with native persistent bore names. Pinned QymCAD omits `Hole.sketch` from its dependency inputs: changing a point can leave the hole's cached body stale. Native parameter marking reads arbitrary persisted feature expressions, permitting a bounded bridge for global and named drivers, but that bridge cannot observe unnamed literal edits or create native datum/projection scheduling edges.

## Decisions

1. Extend `hole` with an exclusive `sketch` branch in place of face/offset placement. Accept `flip`, default false; default `points` to every isolated native point. The pin has no point-subset recipe: an explicit list must contain the complete isolated-point set exactly once; refuse proper subsets, unknown IDs and duplicates. Keep existing diameter, depth/through, plain/counterbore/countersink fields and precision/domain guards. All four size inputs use the native formula door with finite numeric strings canonicalized to round-trippable decimal text (including exponent notation). Reject face-only placement fields in this branch. Require stock/sketch in the same part and prior timeline positions; enter the source's owner context for the native adder.
2. Persist reserved `sketch_dep_*` entries in the hole's ordinary `feat_dims`. Capture coordinate-constraint and relevant sketch-item expressions, upstream expression reads and native dimension names. Reconcile after creation, engine parameter/dimension/sketch changes and open; remove obsolete reserved entries while preserving real hole dimensions and unrelated metadata. No dummy geometry, invented driver names or `0*driver` contamination of hole dimensions.
3. Extend engine dependency closure with Hole→sketch and named coordinate sources→owning sketches/holes. Resolve every feature and sketch recipe expression read, including ordinary size/transform formulas, Point drivers and persisted `sketch_dep_*` entries, through global parameter aliases and native named dimension targets to their owner nodes; sketch-item targets belong to their sketch. This applies to independent feature consumers and plain Point sketches too, without a hole. Global parameters themselves have no feature owner. Non-cascade source deletion names dependent features/sketches/holes; cascade removes them and downstream consumers under the existing history contract. Use it for dirty propagation, affected-body snapshots/retries, F-024 query preflight and structural deletion checks. Mark affected holes dirty for direct engine sketch edits and on open so stored caches are rebuilt. Refuse deleting a used sketch without cascade; explicit cascade deletes its holes and downstream consumers. Refuse deleting a used isolated point until its hole is deleted; keep deletion and failed downstream edits atomic, retaining F-074 validation and original archive/B-rep state.
4. Support world-plane sketches, settled fixed datum frames and hosted faces only when the host belongs to the source's own upstream body lineage, whose native source edge already orders preparation. Apply this bounded-support policy to every sketch reached through the marker’s complete source graph, including transitive named coordinate/reference measurements, global aliases, feature formulas and placement inputs. Every source sketch must also have a native sketch-array index strictly less than the marker's: the app solves sketches in array order, regardless of timeline order. Refuse later sources, naming the source and saying it is solved after the marker. Refuse parameterized/named datum ancestors, projected source sketches and independent face hosts, identifying the unsupported source. A persisted formula is a dirty trigger, not a structural scheduler edge; creation, later parameter/dimension/sketch edits and evaluated open/rebuild guards enforce the same policy atomically, retaining the exact pre-edit archive on refusal.
5. Keep through as the existing fixed 10000 mm depth. Before creation and after evaluated edits/open/rebuild, project all eight corners of the current source bbox onto the directed drilling axis from the marker plane. Refuse a required positive span above 10000 mm; this conservative span includes air before the stock. It is not native through-all. Require positive finite dimensions; recess diameter exceeds bore diameter and recess depth lies strictly inside total depth. Reject `dimension_set off_u/off_v` for sketch holes, since native sketch placement ignores them. An explicit depth edit converts through to blind; naming alone keeps through. Reconcile native app depth edits on engine open by clearing the through marker when an explicit depth expression exists.
6. Require a positive finite-area bore face for every requested point via `p.names.get(face_id)` matching `GeoName{feature:hole, role:Hole, src:point_id}`. A missing site refuses the whole operation naming its point ID, including off-stock, void and overlap cases. Aggregate cut success/volume alone is insufficient. Preserve batch, undo, native point IDs and existing face-hole behavior.
7. Document the app limit in tool descriptions and coverage: global coordinate expressions and named point drivers update supported saved holes; unnamed literal dimension edits and structural sketch edits in the app can leave them stale until this engine reopens/rebuilds/reconciles them. Coverage P8 stays **partial**. Full associativity, proper point subsets and dynamic support ordering require an upstream recipe/scheduler change and new validation.

## Consequences

Agents can create native editable hole features at isolated sketch markers while retaining verified global/named coordinate edits after save/load. The engine owns broader transaction/deletion closure than the pinned native app. Refusals expose the pin's operand and scheduling limits rather than claiming full P8 support. Assemblies and native clone/remap repair remain outside this stage's scope. Global parameters remain outside timeline cascade: an alias explicitly reading a deleted named driver must be deleted separately before reevaluation; structural feature/sketch/hole consumers are removed.
